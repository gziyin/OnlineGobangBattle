## 三、浏览器联调流程

### 3.1 前置准备

1. 启动服务器（端口 8080）
2. 确保数据库已初始化（用户表存在）
3. 准备两个测试用户账号

### 3.2 完整对战流程测试

**步骤 1：登录**
- 打开浏览器访问 `http://localhost:8080/login.html`（或实际登录页面）
- 使用测试用户 A 登录
- 验证 token 存入 localStorage

**步骤 2：进入大厅**
- 登录成功后自动跳转到 `hall.html`
- 验证用户信息显示正确（用户名、分数）
- 验证 WebSocket 连接状态为"已连接"

**步骤 3：开始匹配**
- 点击"开始匹配"按钮
- 验证状态变为"正在匹配..."
- 验证等待计时器开始计时

**步骤 4：第二个用户匹配**
- 打开另一个浏览器窗口（或无痕模式）
- 使用测试用户 B 登录
- 点击"开始匹配"

**步骤 5：匹配成功**
- 两个窗口都应显示"匹配成功！"
- 验证 2 秒后自动跳转到 `room.html?room_id=xxx&color=xxx`
- 用户 A 应为黑子（先手），用户 B 应为白子

**步骤 6：游戏房间**
- 验证棋盘正确显示（15×15 网格）
- 验证玩家信息区显示双方用户名和分数
- 验证轮次指示器显示"轮到你了"（黑方）和"等待对手落子"（白方）

**步骤 7：落子测试**
- 黑方点击棋盘任意位置落子
- 验证黑方窗口显示棋子（黑色）
- 验证白方窗口同步显示棋子
- 验证轮次切换到白方

**步骤 8：交替落子**
- 白方落子
- 验证双方窗口同步更新
- 重复几次，验证落子同步正常

**步骤 9：认输测试**
- 点击"认输"按钮
- 验证弹出确认对话框
- 确认认输
- 验证双方都显示游戏结束弹窗
- 验证胜方显示"你赢了！"，负方显示"你已认输"
- 验证积分变化显示正确

**步骤 10：返回大厅**
- 点击"返回大厅"按钮
- 验证跳转回 `hall.html`
- 验证可以重新开始匹配

### 3.3 五子连珠胜利测试

1. 重复步骤 1-6
2. 黑方连续落子形成五连（横、竖或斜）
3. 验证第 5 颗棋子落下后触发胜利判定
4. 验证双方都显示"你赢了！"或"你输了"
5. 验证积分更新

### 3.4 断线重连测试

1. 游戏进行中断开 WebSocket（如关闭网络或刷新页面）
2. 重新打开页面并登录
3. 验证发送 `game.reconnect` 事件
4. 验证收到完整棋盘状态
5. 验证棋盘正确恢复
6. 验证可以继续落子

## 四、常见问题排查

### 4.1 编译错误

| 错误类型 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 找不到头文件 | CMakeLists.txt 路径错误 | 检查 include_directories 配置 |
| 链接错误 | 库文件未链接 | 检查 target_link_libraries |
| 未定义符号 | 源文件未加入编译 | 检查 add_executable/add_library |

### 4.2 运行时错误

| 错误类型 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 端口占用 | 其他进程占用 8080 | 更换端口或关闭占用进程 |
| 数据库连接失败 | MySQL 未启动或配置错误 | 检查数据库配置和服务状态 |
| WebSocket 握手失败 | 路由配置错误 | 检查 WebSocket 路径配置 |

### 4.3 前端问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 页面空白 | JavaScript 错误 | 打开浏览器控制台查看错误 |
| WebSocket 连接失败 | 地址/端口错误 | 检查 websocket.js 中的 URL |
| 落子无反应 | 事件未发送 | 检查浏览器控制台网络请求 |
| 棋盘不同步 | 事件处理错误 | 检查 game.js 中的事件处理器 |
