## 一、背景

M3 阶段核心能力已完成（2026-05-25），包括：

- `online.hpp` - 四态在线状态管理（OFFLINE/HALL_IDLE/MATCHING/IN_ROOM）
- `connection_manager.hpp` - WebSocket 连接管理（唯一暴露 connection_hdl）
- `block_queue.hpp` - 线程安全阻塞队列
- `matcher.hpp` - 三段位分桶匹配器
- `websocket_handler.hpp` - WebSocket 事件分发处理器
- `hall.html` / `websocket.js` - 游戏大厅前端

M4 阶段目标：完成游戏房间管理、五子棋对战逻辑（落子/胜负判定）、对战前端界面、断线重连机制，实现完整的对战闭环。

## 二、模块化开发策略

**原则**：实现一个模块 -> 编写测试 -> 测试通过 -> 再进入下一个模块

### 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 房间 ID 生成 | **内存自增 + 时间戳前缀** | 避免依赖数据库，满足单机场景，格式如 `R1716700001` |
| 棋盘存储 | **内存中 15×15 数组** | 复用 M1 的 `board_to_str/str_to_board`，读写高效 |
| 胜负判定 | **每次落子后检查四方向** | 五子棋标准算法，复杂度 O(1)（仅检查新落子周围） |
| 超时判负 | **可配置超时时间** | 默认 60 秒/步，防止恶意拖延 |
| 断线重连 | **房间状态保持 + 重连事件** | 断线不立即判负，保留 60 秒重连窗口 |
| 认输协议 | **客户端发送 game.giveup** | 服务端直接判负，无需确认 |
| 和棋协议 | **暂不实现** | M4 聚焦核心对战，和棋留到 M5 优化 |

### 模块依赖关系

```text
WebSocket 回调层
    ├── ConnectionManager   （封装 WebSocket++，仅此层可见 connection_hdl）
    └── websocket_handler   （事件分发）

RoomManager
    ├── OnlineManager       （状态校验：IN_ROOM）
    └── ConnectionManager   （发送消息）

GameRoom
    ├── 棋盘状态            （15×15 数组）
    ├── 落子逻辑            （合法性校验 + 胜负判定）
    └── 定时器              （超时判负）

业务模块（RoomManager、GameRoom 等）
    └── 只 #include "online.hpp"，不可见 connection_hdl
```

**硬性约束**：`connection_hdl` 只允许出现在 `connection_manager.hpp` 和 WebSocket 接线层，禁止渗透到任何业务头文件。

#### 1.2 数据结构设计

```cpp
// room.hpp —— 游戏房间管理，不依赖 WebSocket++

enum class RoomStatus {
    WAITING  = 0,  // 等待玩家就绪
    PLAYING  = 1,  // 游戏进行中
    FINISHED = 2   // 游戏已结束
};

enum class PieceColor {
    BLACK = 1,  // 黑子先行
    WHITE = 2
};

enum class GameResult {
    NONE     = 0,  // 进行中
    BLACK_WIN = 1,  // 黑胜
    WHITE_WIN = 2,  // 白胜
    DRAW     = 3,  // 平局（暂不使用）
    TIMEOUT  = 4,  // 超时判负
    GIVEUP   = 5   // 认输
};

struct PlayerInfo {
    int64_t     user_id;
    std::string username;
    PieceColor  color;
    bool        ready;
};

class GameRoom {
public:
    GameRoom(const std::string& room_id, int64_t player1_id, int64_t player2_id);

    // 获取房间信息
    std::string get_room_id() const;
    RoomStatus get_status() const;
    
    // 落子（返回游戏结果，NONE 表示继续）
    GameResult place_piece(int64_t user_id, int row, int col);
    
    // 认输
    GameResult give_up(int64_t user_id);
    
    // 获取当前棋盘状态（用于重连）
    std::string get_board_state() const;
    
    // 获取当前轮到谁
    int64_t get_current_turn() const;
    
    // 获取玩家信息
    bool get_player(int64_t user_id, PlayerInfo& out) const;
    bool get_opponent(int64_t user_id, PlayerInfo& out) const;
    
    // 检查用户是否在此房间
    bool has_player(int64_t user_id) const;

private:
    // 胜负判定（检查四方向：横、竖、两条对角线）
    bool check_win(int row, int col, PieceColor color) const;
    
    // 检查落子是否合法
    bool is_valid_move(int row, int col) const;

    std::string room_id_;
    RoomStatus status_;
    int board_[15][15];  // 0=空, 1=黑, 2=白
    PlayerInfo players_[2];
    int current_turn_;  // 0 或 1，指向 players_ 索引
    int move_count_;
    int64_t last_move_time_;
};
```

```cpp
class GameController {
public:
    void init(RoomManager* room_mgr, OnlineManager* online_mgr, 
              ConnectionManager* conn_mgr, UserTable* user_table);
    
    // 处理落子事件
    void handle_move(int64_t user_id, int row, int col);
    
    // 处理认输事件
    void handle_giveup(int64_t user_id);
    
    // 处理游戏开始（匹配成功后调用）
    void handle_game_start(int64_t player1_id, int64_t player2_id);
    
    // 处理断线
    void handle_disconnect(int64_t user_id);
    
    // 处理重连
    void handle_reconnect(int64_t user_id);

private:
    // 游戏结束处理（更新分数、发送结果、销毁房间）
    void on_game_over(const std::string& room_id, GameResult result, 
                      int64_t winner_id, int64_t loser_id);
    
    // 发送消息给房间内所有玩家
    void broadcast_to_room(const std::string& room_id, const std::string& msg);
    
    // 启动超时检测定时器
    void start_timeout_timer(const std::string& room_id);

    RoomManager* room_mgr_;
    OnlineManager* online_mgr_;
    ConnectionManager* conn_mgr_;
    UserTable* user_table_;
};
```

#### 2.2 超时机制

- 每步落子超时时间可配置（默认 60 秒）
- 使用 `std::thread` + `std::condition_variable` 实现定时器

## 五、风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 胜负判定逻辑错误 | 中 | 高 | 充分单元测试覆盖各种连珠形态 |
| 断线重连状态不一致 | 中 | 高 | 重连时发送完整棋盘状态，而非增量 |
| 超时定时器资源泄漏 | 中 | 中 | 使用 RAII 管理定时器线程，房间销毁时自动清理 |
| 并发落子竞态条件 | 中 | 高 | 房间内操作加锁，保证原子性 |
| 前端状态残留 | 中 | 中 | 游戏结束强制重置状态，清理事件监听 |
| `connection_hdl` 依赖渗透 | 低 | 高 | Code Review 检查业务头文件，架构约束验收项兜底 |
