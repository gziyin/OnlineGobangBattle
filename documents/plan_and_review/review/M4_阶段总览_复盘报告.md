## 三、技术方案总览

### 3.1 对战数据流

```text
match.success (Matcher)
    → GameController::handle_game_start()
    → RoomManager::create_room()
    → game.start 广播双方
    → 客户端 room.html 渲染棋盘

game.move (客户端)
    → WebSocketHandler::handle_game_move()
    → GameController::handle_move()
    → GameRoom::place_piece() + 胜负判定
    → game.move / game.over 广播

断线
    → handle_disconnect() → reconnect.available
    → game.reconnect / reconnect.accept → 恢复棋盘状态
```

### 3.2 关键设计决策（与计划一致）

| 决策 | 选择 | 结果 |
|------|------|------|
| 房间 ID | 内存自增 + 时间戳前缀 | 已落地 |
| 棋盘存储 | 15×15 内存数组 | 已落地 |
| 胜负判定 | 落子后四方向检查 | 已落地 |
| 超时判负 | 可配置（默认 60 秒/步） | 已落地 |
| 和棋 | M4 不实现 | 按计划跳过 |

### 3.3 与 M3 的衔接

- M3 冻结的 15 个 WebSocket 事件名与 4 态 `OnlineStatus` 在 M4 中保持不变。
- `match.success` 后由 `GameController` 接管，将双方状态置为 `IN_ROOM`。
- 对局结束后回退 `HALL_IDLE`，与 M3 大厅流程衔接。
