### 3.1 架构分层

```

│                   前端展示层                              │
│  client/hall.html（三态 UI: idle / matching / matched）  │

│  connection_manager.hpp（唯一暴露 connection_hdl）        │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                   业务逻辑层                              │
│  matcher.hpp（三段位分桶 + 超时跨段 + 懒删除）            │
│  online.hpp（四态在线管理，不依赖 WebSocket++）           │
│  matcher_interface.hpp（抽象接口 + MatchResult 定义）     │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                   基础设施层                              │
│  block_queue.hpp（线程安全阻塞队列，timed_pop/shutdown）  │
│  db.hpp / security.hpp / auth_*.hpp（M2 复用）            │
└─────────────────────────────────────────────────────────┘
```

### 3.2 核心设计模式

| 模式 | 应用位置 | 收益 |
|------|----------|------|
| **接口隔离** | `matcher_interface.hpp` vs `matcher.hpp` | WebSocket 层只依赖抽象接口，匹配实现可独立演进 |
| **双管理器** | `OnlineManager` + `ConnectionManager` | 业务状态与连接句柄彻底解耦，`connection_hdl` 不渗透 |
| **懒删除** | `Matcher::cancel()` 打 cancelled 标记 | 避免并发删除带来的复杂锁竞争 |
| **生产者-消费者** | `BlockQueue` + `Matcher::match_loop()` | 匹配请求入队与消费线程解耦 |
| **策略模式** | `score_to_tier()` 计算段位 | `tier` 不持久化，消除数据不一致风险 |
| **回调通知** | `set_match_callback()` | 匹配成功后由 WebSocket 层负责发送，Matcher 不持有连接 |

### 3.3 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 在线状态模型 | 四态（OFFLINE/HALL_IDLE/MATCHING/IN_ROOM） | 覆盖匹配闭环，便于 M4 扩展房间状态 |
| 连接管理方案 | 双管理器 | `OnlineManager` 不暴露 `connection_hdl`，彻底隔离 WebSocket++ 依赖 |
| 阻塞队列接口 | 仅 `timed_pop()` + `is_shutdown()` | 消费线程通过返回值 + 状态区分超时与关闭，不会卡死 |
| 匹配策略 | 三段位分桶 + 超时跨段 | 实现复杂度可控，与总项目计划一致 |
| 取消策略 | 懒删除 | 出队时校验，避免并发删除的锁竞争 |
| tier 字段 | 不存入 `MatchRequest` | 由 `score_to_tier()` 动态计算，消除 score/tier 不一致 |
| WebSocket 鉴权 | 建连后按事件携带 token 校验 | 与 M2 JWT 体系兼容，改动最小 |
| room_id 来源 | 进程内自增 | M3 最小闭环，M4 可切换为数据库主键 |
| 前端状态 | 三态（idle/matching/matched） | 最小闭环覆盖，异常断线可重置回 idle |

## 六、核心知识点总结

### 6.1 connection_hdl 隔离模式

| 层级 | 可见性 | 理由 |
|------|--------|------|
| `connection_manager.hpp` | ✅ 可见 | 唯一管理连接句柄的业务文件 |
| `websocket_handler.hpp` | ✅ 可见 | WebSocket 接线层，直接操作连接 |
| `online.hpp` | ❌ 不可见 | 纯业务状态，不依赖 WebSocket++ |
| `matcher.hpp` | ❌ 不可见 | 匹配逻辑不接触连接 |
| `block_queue.hpp` | ❌ 不可见 | 通用队列，无网络依赖 |

> **硬性约束**: `connection_hdl` 只允许出现在 `connection_manager.hpp` 和 WebSocket 接线层，禁止渗透到任何业务头文件。

### 6.2 三段位分桶匹配策略

| 段位 | 分数范围 | 匹配规则 |
|------|----------|----------|
| BRONZE | 0 ~ 1299 | 同段优先，超时后放宽至 SILVER |
| SILVER | 1300 ~ 1699 | 同段优先，超时后放宽至相邻段 |
| GOLD | 1700+ | 同段优先，超时后放宽至 SILVER |

### 6.3 BlockQueue timed_pop 语义

| 返回值 | `is_shutdown()` | 含义 |
|--------|-----------------|------|
| `true` | 无关 | 成功取出数据，`out` 有效 |
| `false` | `false` | 超时，正常继续循环 |
| `false` | `true` | 队列已关闭，准备退出 |

```cpp
void Matcher::match_loop() {
    MatchRequest req;
    while (!queue_.is_shutdown()) {
        if (queue_.timed_pop(req, 100)) {
            process(req);
        }
        // 超时间隙可做懒删除条目的定期清理
    }
}
```

### 6.4 WebSocket 事件协议

**客户端 -> 服务端（上行 3 个）**

### 6.5 断线处理顺序

统一约定断线清理链路：


## 七、经验教训

### 7.1 做得好的地方

1. **架构约束严格执行**
   - `connection_hdl` 隔离模式从一开始就确立并贯穿始终
   - 双管理器设计使业务层完全不感知 WebSocket++ 依赖
   - MatcherInterface 抽象接口让 WebSocket 层与匹配实现解耦

2. **懒删除策略简化并发控制**
   - 取消时只打 `cancelled` 标记，出队时校验
   - 避免了队列中间元素的复杂删除操作和锁竞争
   - 断线用户通过 `on_disconnect` 复用同一机制

3. **收尾验证彻底**
   - `MatchResult` 唯一定义来源统一
   - `Matcher` 继承 `MatcherInterface`
   - `test_connection_manager` 从模拟测试改为真实 WebSocket 环境
   - CTest 接线补全，全量构建与测试通过

### 7.2 需要改进的地方

1. **WebSocket++ 兼容性应提前验证**
   - 花费了 4 个提交修复 config 类型探测和兼容问题
   - **改进**: 在项目初期或 Phase 规划阶段就确认依赖库版本和 API 差异

2. **共享类型定义应提前冻结**
   - `MatchResult` 重复定义、`MatcherInterface` 与 `Matcher` 未统一
   - **改进**: 开发开始前先冻结共享类型定义，作为公共契约

3. **测试应尽早用真实环境验证**
   - `test_connection_manager` 初始为模拟式测试，收尾时才改为真实环境
   - **改进**: 对依赖外部库的模块，优先设计真实环境测试

4. **收尾验证周期较长**
   - 核心开发在 4 月完成，收尾验证到 5 月底
   - **改进**: 核心开发完成后立即进入验证，避免间隔过长导致上下文丢失

|------|------|------|------|
| WebSocket 状态与在线表不一致 | 低 | 高 | ✅ 统一 `handle_disconnect()` 链路 |
| 并发下重复匹配 | 低 | 高 | ✅ 出队二次校验 + 用户状态校验 |
| `connection_hdl` 依赖渗透 | 极低 | 高 | ✅ 架构约束 + Code Review 兜底 |
| 匹配线程无法优雅退出 | 极低 | 中 | ✅ `BlockQueue::shutdown()` 保证退出 |
| 前端状态残留 | 低 | 中 | ✅ 三态 UI + 异常断线重置 |
| room_id 内存生成丢失 | 低 | 中 | ⚠️ M4 需切换为持久化房间管理 |
