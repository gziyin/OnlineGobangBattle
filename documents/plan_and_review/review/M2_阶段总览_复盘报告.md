## 三、技术方案总览

### 3.1 架构分层

```
┌─────────────────────────────────────────────────────────┐
│                    HTTP API 层                            │
│  auth_handler.hpp (handle_register/handle_login)         │
│  auth_middleware.hpp (extract_user_id_from_token)        │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                    业务逻辑层                            │
│  security.hpp (pbkdf2_hash/pbkdf2_verify/jwt_generate)   │
│  user_table.hpp (insert/select/update)                   │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                    数据访问层                            │
│  db.hpp (DBPool::get_connection/return_connection)       │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                    MySQL 数据库                           │
│  user 表 (id, username, password_hash, score, ...)       │
└─────────────────────────────────────────────────────────┘
```

### 3.2 核心设计模式

| 模式 | 应用位置 | 收益 |
|------|----------|------|
| **RAII** | DBPool::ConnGuard、lock_guard | 资源自动管理，防止泄露 |
| **接口分离** | select_for_auth vs select_by_username | 安全性提升，密码不泄露 |
| **事务** | update_score_match | 原子性保证 |
| **工厂模式** | _create_connection() | 连接创建隔离 |
| **生产者 - 消费者** | 连接池队列 | 并发安全 |
| **TOCTOU 防护** | handle_register | 并发注册冲突处理 |

### 3.3 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 认证方案 | 纯 JWT | 无状态、易扩展、简化 Phase 4 |
| 密码加密 | OpenSSL PBKDF2 | Rocky 9 自带，0 依赖风险 |
| 连接池超时 | 3 秒超时 | 防止并发场景死锁 |
| 密码哈希参数 | 10000 次迭代，SHA256 | 符合 OWASP 推荐 |
| Token 过期时间 | 24 小时（86400 秒） | 平衡安全性与用户体验 |

## 六、核心知识点总结

### 6.1 线程安全三件套

| 组件 | 作用 | 为什么需要 |
|------|------|------------|
| `mutex` | 互斥锁 | 同一时间只有一个线程能操作队列 |
| `lock_guard` | RAII 包装器 | 构造时加锁，出作用域自动解锁 |
| `condition_variable` | 条件变量 | 线程等待时睡过去，有连接时被叫醒 |

### 6.2 MySQL C API 绑定规则

> **凡是 MYSQL_TYPE_LONG → 对应 C++ 变量必须是 `int` 或 `unsigned int`（32 位），不能用 `unsigned long`（64 位）**

| MYSQL_TYPE_xxx | C++ 对应类型 |
|----------------|-------------|
| MYSQL_TYPE_LONG | `int` / `unsigned int` |
| MYSQL_TYPE_LONGLONG | `int64_t` / `uint64_t` |
| MYSQL_TYPE_STRING | `char[]` + `unsigned long length` |
| MYSQL_TYPE_TINY | `int` / `char` |

### 6.3 PBKDF2 参数选择

| 参数 | 值 | 说明 |
|------|-----|------|
| 迭代次数 | 10000 | OWASP 2023 推荐最低值 |
| 盐长度 | 16 字节 (128 位) | 足够随机性 |
| 密钥长度 | 32 字节 (256 位) | SHA256 输出长度 |
| 哈希算法 | SHA256 | 标准安全哈希 |

### 6.4 安全编码实践

| 风险 | 应对措施 |
|------|----------|
| 用户名枚举 | 模糊错误信息（用户名不存在/密码错误返回相同提示） |
| 密码泄露 | 返回信息不包含 password_hash |
| 并发注册冲突 | TOCTOU 防护（insert 失败后重查） |
| 时序攻击 | 使用 `CRYPTO_memcmp` 常数时间比较 |
| SQL 注入 | 全部使用预处理语句 |

### 6.5 JWT 结构

```
header.payload.signature

# Header (Base64)
{"alg":"HS256","typ":"JWS"}

# Payload (Base64)
{"user_id":"12345","iat":1713000000,"exp":1713086400}

# Signature
HMACSHA256(base64url(header) + "." + base64url(payload), secret)
```
